# Nhập kho & lịch sử tồn — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mọi thay đổi tồn của biến thể đều có dòng trong sổ kho; có phiếu nhập, điều chỉnh tồn, màn Kho và khối lịch sử ở trang sản phẩm; form sản phẩm không còn ghi đè tồn.

**Architecture:** Sổ kho ghi bằng **trigger** trên `product_variants` (insert / update `stock` / delete), nên không đường nào đổi tồn mà lọt sổ. Hàm SQL nào đổi tồn thì gọi `set_stock_context(...)` trước để trigger biết loại, đơn / phiếu liên quan; không có ngữ cảnh thì trigger ghi "Điều chỉnh · Sửa trực tiếp". Phiếu nhập và điều chỉnh là hai hàm `admin_*` mới; màn hình đọc qua hai view `security_invoker`.

**Tech Stack:** Next.js 16 App Router (Server Components + Server Actions), Supabase Postgres (plpgsql, RLS), Tailwind v4, zod, Playwright.

**Spec:** [docs/superpowers/specs/2026-10-30-nhap-kho-design.md](../specs/2026-10-30-nhap-kho-design.md)

- [ ] **Step 4: Viết migration `20261030000001_stock_ledger.sql`**

Theo thứ tự: enum → sequence + 3 bảng + index → `set_stock_context` → trigger → hàm `admin_*` sửa lại → hàm mới → view → RLS / grant → dòng Tồn đầu cho dữ liệu cũ.

Trigger (thuật toán cố định, viết đúng như sau):

```sql
create or replace function public.log_stock_change()
returns trigger language plpgsql security definer set search_path = '' as $$
declare
  v_ctx jsonb := nullif(current_setting('app.stock_ctx', true), '')::jsonb;
  v_row public.product_variants%rowtype := case when tg_op = 'DELETE' then old else new end;
  v_delta integer;
  v_kind public.stock_movement_kind;
  v_reason public.stock_adjust_reason;
  v_note text;
begin
  if tg_op = 'INSERT' then
    v_delta := new.stock; v_kind := 'initial';
  elsif tg_op = 'UPDATE' then
    v_delta := new.stock - old.stock;
    v_kind := coalesce((v_ctx ->> 'kind')::public.stock_movement_kind, 'adjust');
    v_reason := case when v_ctx is null then 'other' else (v_ctx ->> 'reason')::public.stock_adjust_reason end;
    v_note := case when v_ctx is null then 'Sửa trực tiếp' else v_ctx ->> 'note' end;
  else -- DELETE
    -- Xóa theo sản phẩm (cascade) thì sản phẩm đã mất: bỏ qua
    if not exists (select 1 from public.products where id = old.product_id) then return old; end if;
    v_delta := -old.stock; v_kind := 'adjust'; v_reason := 'other'; v_note := 'Xóa biến thể';
  end if;
  if v_delta = 0 then return case when tg_op = 'DELETE' then old else new end; end if;

  insert into public.stock_movements (variant_id, product_id, name_snapshot, variant_snapshot, sku_snapshot,
    kind, reason, note, delta, stock_after, order_id, receipt_id)
  select case when tg_op = 'DELETE' then null else v_row.id end, v_row.product_id, p.name,
    coalesce(public.variant_label(v_row.id),
             (select nullif(string_agg(value, ' · '), '') from jsonb_each_text(v_row.option_values))),
    v_row.sku, v_kind, v_reason, v_note, v_delta, v_row.stock + case when tg_op = 'DELETE' then v_delta else 0 end,
    (v_ctx ->> 'order_id')::uuid, (v_ctx ->> 'receipt_id')::uuid
  from public.products p where p.id = v_row.product_id;
  return case when tg_op = 'DELETE' then old else new end;
end; $$;

create trigger product_variants_stock_log after insert or update of stock on public.product_variants
  for each row execute function public.log_stock_change();
create trigger product_variants_stock_log_delete before delete on public.product_variants
  for each row execute function public.log_stock_change();
```

(Lúc DELETE, `variant_id` để null ngay vì dòng biến thể sắp mất; `stock_after` = 0.)

Sửa các hàm cũ (chép thân hàm từ migration gốc, chỉ thêm những dòng sau):
- `admin_save_product` (`20261029000005`): bỏ dòng `stock = (x.item ->> 'stock')::integer,` trong `update public.product_variants`. Insert biến thể mới giữ nguyên.
- `admin_save_order` (`20261029000006`): trước khối trả kho khi sửa đơn → `perform public.set_stock_context('return', v_id, p_note => 'Sửa đơn ' || v_order.code);` Trước vòng lặp trừ kho → `perform public.set_stock_context('sale', v_id);`
- `admin_set_order_status` (`20261029000006`): trước `update … stock = v.stock + x.qty` → `perform public.set_stock_context('return', v_order.id, p_note => case p_status when 'cancelled' then 'Hủy đơn' else 'Khách trả hàng' end);`
- `quote_create_order` (`20261029000007`): trước vòng lặp → `perform public.set_stock_context('sale', v_order.id);`

Hàm mới:
- `admin_adjust_stock`: kiểm admin; `p_delta = 0` → `Nhập số thay đổi khác 0.`; `p_reason = 'other'` và ghi chú trống → `Chọn "Khác" thì cần ghi chú lý do.`; `set_stock_context('adjust', p_reason => p_reason, p_note => nullif(trim(p_note), ''))`; `update … set stock = stock + p_delta where id = p_variant_id and stock + p_delta >= 0 returning stock`; không thấy biến thể → `Không tìm thấy phân loại.`; thấy mà không update được → `Tồn sau điều chỉnh không được âm (hiện còn %).`
- `admin_create_stock_receipt`: kiểm admin; không có dòng → `Phiếu nhập cần ít nhất 1 sản phẩm.`; qty ngoài 1..100000 → `Số lượng nhập phải từ 1 đến 100000.`; insert phiếu (`created_by = auth.uid()`); gộp theo `variant_id`, chèn `stock_receipt_items` kèm snapshot (tên SP, `variant_label`, SKU); `set_stock_context('receipt', p_receipt_id => id, p_note => code)`; cộng kho; biến thể không tồn tại → `Có sản phẩm trong phiếu không còn tồn tại.`

RLS / quyền: bật RLS 3 bảng; policy `for select to authenticated using ((select public.is_admin()))` cho cả 3; `stock_receipts` và `stock_receipt_items` thêm policy insert cho admin (hàm `security invoker`); `stock_movements` không cấp insert / update / delete cho `authenticated` (chỉ trigger `security definer` ghi). `grant select` hai view cho `authenticated`. `set_stock_context` grant `authenticated`.

Dữ liệu cũ: `insert into stock_movements (…, kind, note, delta, stock_after, created_by) select …, 'initial', 'Tồn đầu khi bật sổ kho', stock, stock, null from product_variants where stock > 0`.
